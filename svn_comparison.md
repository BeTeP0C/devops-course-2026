# Git и SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?
Ветка в Git — лишь подвижная ссылка на коммит в локальном репозитории: создаётся за доли
секунды без обращения к серверу и без копирования файлов. В SVN ветка создаётся копированием
каталога (`svn copy`) на сервере, каждое действие идёт через сеть, а слияние веток требует
ручного отслеживания изменений — поэтому ветвиться в SVN дорого и неудобно.

## 2. Можно ли в SVN сделать коммит без интернета?
Нельзя: история хранится только на центральном сервере, и `svn commit` сразу отправляет
изменения туда. Без связи с сервером (по интернету или локальной сети) коммит не выполнится.
В Git можно делать коммиты офлайн и отправить их позже одним `git push`.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
- Старые проекты с многолетней историей и отлаженными процессами, где переезд не окупится.
- Репозитории с тяжёлыми бинарниками (дизайн, игры, чертежи): блокировка файлов и частичная
  выгрузка только нужной папки.
- Организации, которым нужен жёсткий централизованный контроль доступа к отдельным каталогам.
